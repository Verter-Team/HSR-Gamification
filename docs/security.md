# Проверка безопасности API

Проверка проводится только на локальной тестовой БД с демо-seed. Она создаёт
и удаляет несколько тестовых попыток. Запустите API на порту 31017, затем:

```bash
cd apps/api
DATABASE_URL='postgresql://...' JWT_SECRET='тот-же-секрет-что-у-API' npm run test:security
npm audit --omit=dev
```

`test:security` проверяет вход без токена, поддельный и неподписанный JWT,
доступ к чужим попыткам, статистике и достижениям, подмену `userId`, лишние
поля, повторное использование UUID, попытку SQL-инъекции, переполнение чисел,
число событий, слишком длинный пароль, большой JSON, CORS и частый подбор
пароля. Скрипт отказывается работать с нелокальной БД.

Проверка 25.09.2026 на тестовой PostgreSQL: все 20 HTTP-проверок прошли.
Перед исправлениями переполнение чисел возвращало 500, 101 событие принималось,
CORS отвечал `*`, шесть неверных паролей подряд не ограничивались. Теперь эти
случаи возвращают 400, 400, отсутствие разрешающего CORS-заголовка и 429.
Отдельно проверены: разрешённый Origin получает точный CORS-заголовок, чужой
Origin - нет; сервер в production отказывает запускаться со стандартным JWT,
коротким webhook-секретом или `CORS_ORIGIN=*`.

Ограничитель частоты хранит состояние в памяти одного процесса API. Для
нескольких реплик понадобится общее хранилище лимитов. Демо-seed создаёт
публично известный пароль `demo` только для вымышленных сотрудников; его нельзя
запускать на БД с реальными данными. Защита от подделки игровых решений станет
проверяемой после подключения `replay()` общего движка. PWA пока не реализована,
поэтому тесты браузерного хранения токена и офлайн-очереди ещё не проводились.
