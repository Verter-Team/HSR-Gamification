# API

Swagger UI доступен по `/api/docs`, OpenAPI JSON - по `/api/docs-json`.
Все маршруты, кроме входа и `/health`, требуют заголовок `Authorization: Bearer <accessToken>`.

## GET /health

Проверяет API и соединение с Postgres. Возвращает `{"status":"ok"}` или 503.

## POST /auth/login

Вход по табельному номеру и паролю:

```json
{ "externalId": "4471", "password": "demo" }
```

Ответ содержит `accessToken`, `tokenType`, `expiresIn` (секунды) и данные
сотрудника. Токен действует 12 часов. Неверные учётные данные возвращают 401.
Пароль хранится в базе только как хеш Argon2.
Не более пяти попыток входа в минуту с одного IP; затем API отвечает 429.

## GET /scenarios

Возвращает активные сценарии с опубликованной версией. У каждого элемента есть
`id`, `slug`, `title`, `versionId`, `version` и `graph`. Черновики не возвращаются.

## POST /attempts

Принимает завершённую попытку и сохраняет события одной транзакцией. Тело:

```json
{
  "attemptId": "5c590082-8e61-44b4-8c2c-6e6d5d7f9451",
  "scenarioVersionId": "fb09dc41-4e9e-4fb7-89df-ec5a626c90c8",
  "startedAt": "2026-09-25T12:00:00.000Z",
  "clientScore": 120,
  "events": [
    { "seq": 0, "nodeId": "first_choice", "optionId": "call_help", "reactionMs": 1800 }
  ]
}
```

Для тайм-аута передайте `optionId: null`. Сервер берёт пользователя из JWT,
поле `userId` в теле запрещено. `scenarioVersionId` берётся из `GET /scenarios`;
клиент генерирует `attemptId` один раз и повторяет тот же UUID при синхронизации.

Сервер сразу пересчитывает прохождение общим движком (`replay()` из
`packages/scenario-engine`) по логу решений. Клиентские очки как результат не
используются: `clientScore` только сверяется с пересчётом. Если лог не сходится с
графом (чужой узел, несуществующий вариант, ответ позже таймера, недоигранный
сценарий) или `clientScore` не совпал, попытка получает `invalid` и в рейтинг не идёт.

Ответ: HTTP 202 и результат подсчёта с наградами:

```json
{
  "attemptId": "...",
  "status": "scored",
  "rewards": {
    "xp": 500, "coins": 20, "firstPass": true, "xpTotal": 1160,
    "levelBefore": 2, "levelAfter": 3, "rank": "Проводник",
    "newAchievements": [{ "code": "lifesaver", "title": "Спасатель", "icon": "heart-pulse", "tier": 3 }],
    "unlockedScenarios": [{ "slug": "emergency-stop", "title": "Задымление в вагоне" }]
  }
}
```

Для отклонённой попытки: `{"attemptId":"...","status":"invalid","reason":"..."}`.
Повтор с тем же содержимым не создаёт дубль и не начисляет награды второй раз,
повтор с другим содержимым возвращает 409.
Одна попытка содержит не более 100 событий, время реакции ограничено одним часом;
не более 20 отправок в минуту с одного IP.

## GET /attempts/:id

Возвращает состояние попытки по её `attemptId`. Если попытка ещё ждёт серверного
подсчёта, `status` равен `submitted`, а `score`, `passed`, `outcome`, `metrics`,
`tracks` и `scoredAt` равны `null`. После успешного подсчёта `status` станет
`scored`, а поля результата заполнятся; отклонённая попытка получит `invalid`.
Ответ также содержит
`scenarioVersionId`, `timeouts`, `avgReactionMs`, `startedAt` и `submittedAt`.
Неизвестный или чужой UUID возвращает 404, некорректный UUID - 400. PWA может
повторять этот запрос после отправки офлайн-попытки.

## GET /achievements

Каталог активных достижений: `code`, `title`, `description`, `icon`, `tier`.

## GET /users/:id/achievements

Тот же каталог для сотрудника, дополненный `unlockedAt` и `attemptId`.
Для ещё не полученного достижения оба поля равны `null`. Доступен только свой
профиль; чужой возвращает 403.

## GET /users/:id/stats

Профиль и сводка сотрудника: `userId`, `displayName`, `orgUnit`, `totalScore`,
`attemptsCount`, `passedCount`, `avgSafety`, `avgLoyalty`, `streakDays`,
`lastAttemptAt`, `updatedAt`. Для нового сотрудника счётчики равны нулю.
Доступен только свой профиль; чужой возвращает 403.

## GET /leaderboard

Рейтинг проводников по опыту (XP), как в Школе 21. Параметр `depotId` (UUID)
ограничивает рейтинг одним депо. `limit` по умолчанию 20, допустимо от 1 до 100.
Ответ: `scope`, `depotId`, `entries`. У записи есть `rank`, `userId`, `displayName`,
`orgUnit`, `tribe`, `xp`, `level`, `title` (звание), `totalScore`, `attemptsCount`,
`passedCount`. Одинаковый опыт и число попыток дают одинаковый ранг.
Ошибочные параметры возвращают 400.

Статистика, опыт и достижения обновляются при подтверждении серверного результата,
проверке коллеги и покупке в магазине.

## Прогресс в духе Школы 21

Подробно о механиках - `docs/gamification.md`.

### GET /me

Сводка профиля: сотрудник, депо, племя, `level` (уровень, опыт, границы уровня,
доля до следующего, звание), `coins`, `reviewPoints` (баллы проверки), счётчики,
`skills` - радар навыков (доля от максимума во всех сценариях и `daysLeft` до
того, как навык выветрится), число достижений и текущий сезон.

### GET /me/map

Граф сценариев: `branches` (ветки с цветами) и `nodes`. У узла есть `status`:
`passed`, `in_progress` (пробовал, не зачёл), `available`, `locked` (не зачтены
сценарии из `requires`) или `soon` (нет опубликованной версии). Также лучший
результат, число попыток, дата последнего зачёта и `freshnessDaysLeft`.

### GET /me/notifications

Уведомления, важные сверху: проверенный коллегой ответ, открытый сценарий,
сценарий, который пора повторить, новые достижения, ответы коллег в очереди,
место племени в сезоне. У каждого есть `type`, `title`, `text`, `link`.

### GET /tribes

Рейтинг племён в текущем сезоне (три календарных месяца). Очки племени - опыт
участников, заработанный в сезоне. Для каждого: участники, очки, место, три
главных вклада, признак `isMine`. Плюс `myContribution` - вклад текущего сотрудника.

## Взаимная проверка

Экономика как в Школе 21: у каждого на старте 2 балла проверки. Сдать ответ
стоит 1 балл, проверить ответ коллеги - заработать 1 балл, 30 XP и 5 коинов.
Автор получает 20 XP за каждый выполненный пункт чек-листа.

- `POST /reviews` - `{ "attemptId": "...", "answer": "..." }`. Ответ на открытый
  вопрос зачтённой попытки. 409 - нет баллов или ответ уже отправлен, 400 - ответ
  короче минимума из сценария.
- `GET /reviews/queue` - ответы коллег по сценариям, которые проверяющий сам зачёл.
  Автор скрыт: видны только уровень и племя.
- `POST /reviews/:id/evaluate` - `{ "checks": ["polite", "action"], "comment": "..." }`.
  Свой ответ проверять нельзя (403), уже проверенный - 409.
- `GET /reviews/mine` - мои ответы с чек-листом, комментарием и оценкой, плюс
  проведённые проверки.
- `POST /reviews/:id/rate` - `{ "helpful": true }`. Автор оценивает проверку;
  полезная приносит проверяющему 3 коина.

## Магазин

- `GET /shop` - каталог наград, баланс коинов, мои заявки.
- `POST /shop/:code/buy` - обмен коинов на награду. Коины списываются, создаётся
  заявка руководителю со статусом `requested`. 409 - не хватает коинов.

Баланс коинов и баллов проверки - сумма записей журнала `points_ledger`. Траты идут
под блокировкой пользователя, поэтому баланс не уходит в минус при параллельных запросах.

## GET /analytics/overview

Только для ролей `supervisor`, `methodologist`, `admin` (остальным 403). Итоги по
игрокам, доля зачтённых попыток по сценариям, шесть самых трудных шагов (доля
ошибок и тайм-аутов, самый частый неверный вариант) и сводка по депо.

## Исходящий webhook `attempt.scored`

Когда сервер подтверждает результат через `replay()`, он сохраняет событие в БД
в той же транзакции, что и очки. При заданных `WEBHOOK_URL` и `WEBHOOK_SECRET`
API отправляет POST на `WEBHOOK_URL`. Пока адрес не задан, события ждут в БД.
Получатель должен вернуть любой 2xx. На ошибку или тайм-аут 5 секунд сервер
повторяет доставку через 5, 10, 20 и 40 секунд; всего не более пяти попыток.
После этого событие получает статус `failed` и доступно для разбора в БД.
Повторная доставка возможна, поэтому получатель должен удалять дубли по
`X-Webhook-Id`.

Заголовки: `X-Webhook-Event: attempt.scored`, `X-Webhook-Id` (UUID события),
`X-Webhook-Timestamp` (ISO 8601), `X-Webhook-Signature: sha256=<hex>`.
Подпись - HMAC-SHA256 с ключом `WEBHOOK_SECRET` от точной строки
`<X-Webhook-Timestamp>.<сырое тело JSON>`. Проверяйте подпись до разбора JSON;
желательно отклонять старые метки времени, чтобы снизить риск повторного запроса.

Тело содержит `event`, `attemptId`, `occurredAt`, `data` с табельным номером,
сценарием, очками, исходом, метриками и треками, а также `xapi` с actor,
completed verb, object и result. `PUBLIC_BASE_URL` определяет базовый URL
для xAPI actor и object. Демо-история из seed webhook не отправляет.
