# Тренажёр проводника ВСМ

Обучающая игра для проводников высокоскоростной магистрали. Проводник проходит
рабочие ситуации (медицинский инцидент, конфликт пассажиров, нештатная ситуация),
принимает решения на время, видит последствия и получает очки компетенций.

Проект команды для трека "Геймификация для ВСМ" на Хакатоне Московского транспорта.

Репозиторий приватный. Права на результат по регламенту хакатона уходят организатору,
публиковать код и скриншоты без письменного согласия нельзя (пп. 14.4-14.5 Положения).

## Что внутри

- `apps/pwa` - приложение проводника. Веб-приложение, которое ставится на телефон как обычное
- `apps/api` - сервер: сценарии, приём результатов, подсчёт очков, достижения, рейтинг
- `packages/scenario-engine` - движок сценариев. Чистая логика без интерфейса, используется и в приложении, и на сервере
- `packages/ui` - общие компоненты интерфейса
- `content` - сценарии в JSON и картинки к ним
- `docs` - документация для сдачи
- `infra` - docker-compose и конфиги для запуска

## Как устроено

Три части, как в ТЗ: приложение, сервер, база.

```
Телефон проводника                Сервер                      База
+-----------------+     HTTPS     +------------------+        +------------+
| PWA             | ------------> | API (NestJS)     | -----> | PostgreSQL |
| - экран игры    |               | - сценарии       |        |            |
| - профиль       | <------------ | - подсчёт очков  |        +------------+
| - рейтинг       |     SSE       | - достижения     |
| - офлайн-кеш    |               | - рейтинг        |
+-----------------+               | - webhook HR/LMS |
        |                         +------------------+
        v                                 ^
+-----------------+                       |
| scenario-engine | <---------------------+
| один пакет для клиента и сервера
+-----------------+
```

Стиль - модульный монолит: один сервер, внутри модули с чёткими границами, отдельное
приложение-клиент. Микросервисы для такого масштаба не нужны.

Главные принципы:

1. Сценарий - это JSON, а не код. Новую ситуацию добавляет методолог без программиста.
2. Движок один и тот же на телефоне и на сервере. Приложение проигрывает сценарий,
   сервер пересчитывает результат по логу решений тем же кодом.
3. Очки считает сервер, а не телефон. Клиент присылает только список решений.
   Так рейтинг нельзя накрутить.
4. Приложение работает без интернета. Сценарий проходится офлайн, результат уходит,
   когда появится связь.
5. Сценарии версионируются. Правка текста не ломает старые результаты.

Подробно: [docs/architecture.md](docs/architecture.md).

## Запуск

```bash
pnpm install
cp infra/.env.example infra/.env
docker compose -f infra/docker-compose.yml up -d postgres
pnpm --filter api prisma migrate dev
pnpm --filter api prisma db seed
pnpm dev
```

Приложение: http://localhost:5173
Сервер: http://localhost:3000
Swagger: http://localhost:3000/api/docs

Тестовый вход: табельный номер `4471`, пароль `demo`.

Полная инструкция: [docs/deploy.md](docs/deploy.md) (появится к сдаче).

## Кто что делает

Команда: два человека пишут код, два занимаются контентом, визуалом и презентацией.

| Кто | Зона | Что делает |
| --- | --- | --- |
| А | Приложение | Движок сценариев, экран прохождения, таймер, шкалы, профиль, рейтинг, офлайн |
| Б | Сервер и база | API, схема базы, подсчёт очков, достижения, seed, Swagger, webhook, деплой |
| В | Контент | Сценарии в таблице по шаблону, проверка прохождения руками, сбор багов, описание сценариев для сдачи |
| Г | Визуал и презентация | Иллюстрации, иконки достижений, презентация, User Flow, демо-видео, репетиция питча |

Подробный план по дням: [docs/architecture.md](docs/architecture.md), раздел 9.
