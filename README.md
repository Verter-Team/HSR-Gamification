# Тренажёр проводника ВСМ

Обучающая игра для проводников высокоскоростной магистрали Москва - Санкт-Петербург.
Проводник проходит рабочие ситуации (посадка, конфликт пассажиров, медицинский
инцидент, задымление), принимает решения на время, видит последствия на двух шкалах -
безопасность и лояльность пассажира - и получает разбор каждого решения.

Геймификация построена по модели Школы 21: опыт и уровни до 21-го, граф сценариев
с открытием следующих, взаимная проверка ответов коллегами за баллы проверки,
сквозные племена из разных депо, навыки, которые выветриваются без практики, коины
и магазин наград. Подробно - [docs/gamification.md](docs/gamification.md).

Проект команды для трека «Геймификация для ВСМ» на Хакатоне Московского транспорта.

Репозиторий приватный. Права на результат по регламенту хакатона уходят организатору,
публиковать код и скриншоты без письменного согласия нельзя (пп. 14.4-14.5 Положения).

## Быстрый старт

```bash
cp infra/.env.example infra/.env
# Замените POSTGRES_PASSWORD и JWT_SECRET в infra/.env
docker compose --env-file infra/.env -f infra/docker-compose.yml up -d --build
docker compose --env-file infra/.env -f infra/docker-compose.yml exec api npm run db:seed
```

- Приложение: http://localhost:8080 (с телефона в той же сети - `http://IP-компьютера:8080`)
- Swagger: http://localhost:3000/api/docs
- Вход: проводник `4471`, руководитель `1001`, пароль `demo`

На Windows при кириллице в пути к папке Docker не собирает образы - обход в
[docs/deploy.md](docs/deploy.md). Там же запуск без Docker и проверки.

## Что внутри

- `apps/pwa` - приложение проводника. Веб-приложение, которое ставится на телефон и работает без сети
- `apps/api` - сервер: сценарии, пересчёт прохождений, опыт, достижения, племена, взаимная проверка, магазин, аналитика
- `packages/scenario-engine` - движок сценариев и правила прогресса. Один код и в приложении, и на сервере
- `content` - сценарии: таблицы участника В, каталог графа и собранные JSON
- `docs` - документация для сдачи
- `infra` - docker-compose и конфиги nginx

## Как устроено

Три части, как в ТЗ: приложение, сервер, база.

```
Телефон проводника                Сервер                      База
+-----------------+     HTTPS     +------------------+        +------------+
| PWA             | ------------> | API (NestJS)     | -----> | PostgreSQL |
| - маршрут       |    /api/      | - replay() лога  |        +------------+
| - прохождение   |               | - опыт, уровни   |
| - проверки      | <------------ | - племена        |
| - рейтинг       |               | - P2P-проверки   |
| - офлайн-очередь|               | - аналитика      |
+-----------------+               | - webhook HR/LMS |
        |                         +------------------+
        v                                 ^
+-----------------+                       |
| scenario-engine | <---------------------+
| один пакет для клиента и сервера
+-----------------+
```

Стиль - модульный монолит: один сервер, внутри модули с чёткими границами, отдельное
приложение-клиент. Микросервисы для такого масштаба не нужны.

Главные принципы:

1. Сценарий - это данные, а не код. Методолог пишет таблицу, скрипт собирает и проверяет граф.
2. Движок один и тот же на телефоне и на сервере. Приложение проигрывает сценарий,
   сервер пересчитывает результат по логу решений тем же кодом.
3. Очки считает сервер. Подделанный лог или ответ после таймера не засчитываются.
4. Приложение работает без интернета. Результат уходит, когда появится связь.
5. Сценарии версионируются. Правка текста не ломает старые результаты.

Подробно: [docs/architecture.md](docs/architecture.md).

## Команды

```bash
npm run install:all   # зависимости всех пакетов
npm run scenarios     # собрать JSON из таблиц content/tables
npm test              # тесты движка и сервера
npm run dev:api       # сервер в режиме разработки
npm run dev:pwa       # приложение на http://localhost:5173
```
